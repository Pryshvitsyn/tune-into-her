independently authored atmosphere. `scripts/generate-intro-brand.cjs` uses existing

height×0.875, centered at `(0.5W,0.46H)`. Native storyboard, RN fallback and GPU use the
same layout/material resources. The GPU samples the full metallic RGBA foreground;
only the logo upload uses premultiplication. Original V4 texture upload is unchanged.
The atmosphere blends into the saved destination palette from2000–6500ms.

The scene remains9000ms; the original V4 material loop remains8000ms. No independent
animation engine or fixed post-animation hold is added. Today is revealed after its
existing destination/access readiness checks, with the established short fade. Home
replay reuses this scene and retains its existing duplicate-tap/lifecycle guards.
A9000ms scene is not a claim of9000ms total cold-start wall time.

## Black-startup mechanism — implemented and verified

The Release path now creates an app-owned opaque `TIHEarlyLaunchWindow` from the same
bundled launch storyboard **before** Expo factory/Updates/JS startup. It becomes key
and visible, commits layout, and waits for native display callbacks before expensive
startup. The temporary cover stays above replacement root views. Handoff requires the
attached Expo loading surface or its intentional first-frame-guarded hide; it is not
an arbitrary splash timeout. The display link and cover are then released.

`assets/launch/EarlyLaunchWindow.swift` is the canonical helper; the existing splash
plugin injects it idempotently into the Swift AppDelegate. Debug keeps its existing
development startup. The later RN/GPU bridge additionally waits for the atmosphere
image and compatible foreground/GPU paint before hiding Expo splash. Normal Release
contains no deliberately injected native pressure work; the explicit native-QA build
flag supports a separate stress check.

The current signed native builds and captured normal/pressure runs verify this mechanism,
with the exact recorded boundaries below; no universal OS-state guarantee is inferred.
Earlier intermittent black startup is not assigned an unproven SDK/cache root cause.
